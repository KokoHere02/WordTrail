# 手机号认证接入

本功能使用阿里云号码认证服务（PNVS）的短信认证 API，不使用短信服务（SMS）套餐。短信只有在配置凭证后才会发送。测试使用替身网关，不会调用阿里云。

## 本地固定验证码测试

需要时，在 IntelliJ IDEA 的后端运行配置中将 **Active profiles** 设置为 `sms-test`，重启后端。此模式固定验证码为 `123456`，点击“获取验证码”只会建立本地验证记录，不调用阿里云、不发送短信；仍需先点击获取，验证码仍有有效期、用途隔离、使用次数和发送频率限制。数据库仍使用当前后端配置，测试会创建或修改真实配置所指向的数据库中的账号和数据，请使用隔离的测试数据库。

测试完成后移除 `sms-test` 并重启后端，恢复阿里云短信认证。该模式不得在生产环境使用；与 `prod` 或 `production` profile 同时启用会拒绝启动。前端独立的 mock 演示模式与此模式不同。

## 上线前配置

1. 备份数据库并停止应用写入。对现有 MySQL 数据库，根据 `src/main/resources/db/init.sql` 中的手机号字段及短信认证表定义制定并执行迁移，再启动新版本。旧账号没有绑定手机号，无法使用新登录入口。MySQL DDL 不支持整体回滚，请先在测试数据库验证迁移。
2. 在服务端环境变量或 Docker Compose 的 `.env` 中配置 `ALIYUN_ACCESS_KEY_ID`、`ALIYUN_ACCESS_KEY_SECRET` 和 `ALIYUN_SMS_SIGN_NAME`。签名名称从号码认证控制台的系统赠送签名中取得；预置模板为 100001、100003、100004、100005。使用仅有 PNVS 发送和校验权限的 RAM 身份，不要把密钥提交到代码库或前端。
3. `SMS_DAILY_LIMIT` 为实例共享数据库的滚动 24 小时发送上限，默认 10；可根据余额设置其他正整数。每个手机号 24 小时最多 5 次，发送间隔 60 秒；每个来源地址 24 小时最多 20 次。计数在调用阿里云前保留，调用失败也计入本地限额。设置阿里云账户和套餐余量告警。
4. 来源地址使用 Servlet 容器提供的远端地址，不信任客户端直接提交的转发头。如部署在反向代理后，需要由可信代理和容器正确配置客户端地址；否则所有用户可能共享代理的 IP 限额。切勿直接信任任意客户端的 X-Forwarded-For。
5. 只在确认配置、费用和额度后，用自己控制的手机号进行少量真实联调。测试代码不会确认真实阿里云权限、签名、模板及运营商送达情况。

注册和登录验证码用途隔离，验证通过后不可重复使用；验证码有效期 5 分钟，最多尝试 5 次。验证码登录时，手机号尚未注册则验证通过后自动创建账户；用户可以登录后在账户安全中通过短信验证设置密码。修改密码及换绑后撤销全部设备会话。更换手机需要在同一个登录会话分别验证原号码和新号码；号码不可用时不提供自助换绑。

API：公开 `POST /api/auth/phone/send`、`/register`、`/password-login`、`/code-login`；登录后可调用 `POST /api/auth/phone/send-auth`、`PUT /api/auth/phone/password` 和 `/binding`。发送用途分别为 `REGISTER`、`LOGIN`、`PASSWORD`、`CHANGE_OLD`、`CHANGE_NEW`。后续邮箱功能尚未实现，数据库仅预留邮箱字段。
